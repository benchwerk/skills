# Bug report reply

1. Read the report (pasted text, issue, or email). Note what the reporter did give: symptom, version, platform, steps, logs.
2. List what is missing to reproduce it. Check: exact steps, expected vs actual result, version/commit, OS and runtime, config, error text or logs, how often it happens, a minimal example.
3. Keep only the 2-5 items that matter most for this bug. Do not ask for what the report already contains.
4. Draft the reply: thank them, say what you understood, ask for the missing items as a short numbered list, say how to get each (e.g. the version command) when it is not obvious.
5. Show the draft only. Do not post or send it.

## Rules

- Do not blame the reporter or say the report is "incomplete" or "unhelpful".
- Do not promise a fix or a date.
- Do not ask for everything on a generic checklist.
- Do not guess a cause or claim the bug is invalid.
- Match the reporter's language; keep it under about 150 words.
- If nothing is missing, say so and draft no request.

## Output

The reply text only, ready to paste, with a greeting, a one-line summary of the problem, the numbered questions, and a friendly close.
